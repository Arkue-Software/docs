# LT-04 — Prueba de estrés del inventario

**Proyecto:** RedVital  
**Ambiente:** QA  
**Herramienta:** Gatling 3.16.0  
**Fecha de ejecución:** 19 de octubre de 2026 (00:18:43 GMT; hora indicada en el informe Gatling)  
**Estado:** Ejecutada — cumplimiento parcial / capacidad objetivo no demostrada.

## 1. Objetivo

Observar la respuesta de RedVital ante una carga objetivo de **200 usuarios virtuales**, identificar rechazos y fallos bajo estrés y verificar, hasta donde permitan las evidencias disponibles, que el Gateway responde después de la ejecución.

## 2. Configuración de ejecución

- **Generador:** Gatling ejecutado desde la máquina Tools de QA.
- **Escenario:** `LT04 - Inventario estres`.
- **Perfil:** incremento progresivo de 0 a 200 usuarios virtuales durante 1 minuto; mantenimiento de 200 usuarios virtuales durante 4 minutos.
- **Duración registrada por Gatling:** 5 min 14 s (la ejecución de Maven terminó en 5 min 22 s).
- **Flujo:** intento de autenticación y consultas repetidas al inventario solo si la autenticación obtiene un token. Los usuarios con autenticación rechazada quedan en espera; no realizan consultas de inventario.
- **Restricción:** se conservaron las protecciones del Gateway; no se deshabilitaron límites de peticiones.
- **Autorización:** carga de 200 usuarios autorizada por el equipo, según confirmación para esta ejecución.

## 4. Verificación posterior

Después de terminar LT-04 se consultó, **desde la máquina Tools**, el recurso `https://10.43.98.220/api/v1/inventario` **sin token**. Resultado:

```text
HTTP 401 - Tiempo 0.025140s
```

El código **401** es esperable para una petición sin autorización y demuestra que el Gateway devolvió una respuesta HTTP después de la prueba. Esta comprobación **no demuestra** por sí sola la disponibilidad de todos los servicios, la integridad de los datos ni la recuperación completa del sistema ante una falla.

Una consulta previa **desde Windows** produjo HTTP 000 y fallo de conexión TCP al puerto 443; al tratarse de un origen de red diferente, esto no se atribuye a una caída de RedVital.

## 5. Análisis y limitaciones

1. **Admisión limitada:** únicamente 10 de 200 intentos de autenticación obtuvieron acceso; 190 fueron rechazados mediante HTTP 429.
2. **Inventario sin errores entre sesiones admitidas:** se registraron 3.104 solicitudes de inventario exitosas, con p95 de 12 ms; esto describe solo la carga que llegó efectivamente a inventario.
3. **Objetivo de estrés no demostrado:** no se sometió al inventario a 200 usuarios autenticados simultáneamente. La tasa global de errores del 5,75 % refleja principalmente la política de admisión y no un fallo de la operación de inventario.
4. **Observabilidad incompleta:** no se recopilaron aquí evidencias de CPU, memoria, reinicios, conexiones de base de datos o errores internos mediante Grafana/Prometheus.
5. **Integridad y recuperación:** faltan comprobaciones de persistencia, consistencia de datos y recuperación integral del sistema; la respuesta HTTP 401 posterior es una verificación de accesibilidad del Gateway, no una validación de esos atributos.

## 6. Conclusión y acciones recomendadas

**Resultado: cumplimiento parcial.** Gatling ejecutó el perfil definido y el Gateway aplicó rechazos HTTP 429 durante la autenticación. Las sesiones admitidas completaron todas sus consultas de inventario correctamente. **No se puede afirmar que RedVital soportó 200 usuarios autenticados**, ni que se verificaron todos los criterios de recuperación e integridad de datos.

Para una futura validación de capacidad, definir con el equipo un procedimiento autorizado de preparación de sesiones de prueba y supervisar CPU, memoria, disponibilidad y bases de datos durante la ejecución. Mantener la evidencia de los rechazos sin desactivar protecciones del sistema por iniciativa propia.
